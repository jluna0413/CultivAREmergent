# Story 1.3: Complete Plants CRUD Provider Implementation

## Status: Ready for Testing

## Story

As a plant management system user,
I want to perform full CRUD operations on plants (create, read, update, delete),
So that I can manage my cultivation inventory with real-time data from the backend.

## Acceptance Criteria

### Functional Requirements

1. Plants provider implements AsyncValue state management for all CRUD operations
2. Provider fetches plants list with pagination using plants_api_client.getPlants()
3. Provider supports creating new plants with plants_api_client.createPlant()
4. Provider supports updating existing plants with plants_api_client.updatePlant()
5. Provider supports deleting plants with plants_api_client.deletePlant()
6. Provider supports fetching individual plant details with plants_api_client.getPlant()
7. Provider handles AsyncValue.loading, .data, and .error states for all operations
8. Provider maintains data consistency across list and individual operations

### Integration Requirements

9. Plants provider integrates with existing plants_api_client service
10. API client uses existing Dio HTTP client configuration from api_client.dart
11. Provider follows existing Riverpod FutureProvider pattern from dashboard implementation
12. Provider maintains compatibility with existing plants feature structure
13. No breaking changes to provider interface or contract

### Quality Requirements

14. Provider follows Riverpod FutureProvider.autoDispose pattern consistently
15. Error handling includes network failures, authentication issues, and server errors
16. Provider is testable with mocked API client
17. Provider includes proper dependency injection for plants_api_client
18. Code follows existing Flutter project patterns and conventions

### Data Models

- Plant: Complete plant data structure with all fields (Freezed)
- PlantCreate: Fields required for plant creation (Freezed)
- PlantUpdate: Optional fields for plant updates (Freezed)
- PaginatedPlantsResponse: Paginated list response with metadata (Freezed)
- PlantsParams: Query parameters for filtering/sorting/pagination
- API Response formats match model structures with JSON serialization

### API Specifications

- GET /plants/api/ - List plants with pagination and filtering
- POST /plants/api/ - Create new plant (returns Plant)
- GET /plants/api/{id} - Get single plant details
- PUT /plants/api/{id} - Update plant (returns updated Plant)
- DELETE /plants/api/{id} - Delete plant (204 No Content)
- Auth: JWT Bearer token (handled by Dio interceptors)
- Errors: 401 (unauth), 404 (not found), 422 (validation), 500 (server)

### Component Specifications

- Provider Type: Riverpod FutureProvider.autoDispose.family with AsyncValue states
- List Provider: plantsListProvider with PlantsParams for filtering/pagination
- Individual Plant: plantProvider for single plant details
- CRUD Operations: Separate FutureProviders for create/update/delete with invalidation
- Convenience Providers: AsyncValue helpers for loading/error/data states
- Dependency Injection: plants_api_client injected via provider
