# Story 1.1: Implement Dashboard Stats API Integration

## Status: Done ✅

## Story

As a user viewing the dashboard,
I want to see real statistics from my grow data,
So that I can track my plants, strains, and activities effectively.

## Acceptance Criteria

### Functional Requirements

1. Dashboard stats cards display live data from backend API instead of static "0" values
2. Stats update automatically when dashboard screen loads
3. API errors are handled gracefully with user-friendly error messages
4. Loading states show during data fetching with skeleton/spinner UI

### Integration Requirements

5. Dashboard provider connects to dashboard_api_client service
6. API client uses existing Dio HTTP client with proper authentication
7. Stats data matches backend API response format (total_plants, active_plants, strains, harvested)
8. No regression in existing dashboard UI layout and styling

### Quality Requirements

9. Provider follows Riverpod AsyncValue pattern for loading/error states
10. Error handling includes network failures, authentication issues, and server errors
11. Code follows existing Flutter project patterns and conventions
