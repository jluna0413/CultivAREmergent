## User Story

**As a** platform administrator and genetics researcher,  
**I want** a hypergraph knowledge base to store strain lineage, breeder relationships, and state restrictions,  
**So that** users can explore ancestry trees, find similar genetics, and the compliance system can enforce geo-restrictions.

## Acceptance Criteria

### AC-1: Node Type Definitions
- [ ] Define `Strain` node type with properties: `name`, `indica_pct`, `sativa_pct`, `thc_pct`, `cbd_pct`
- [ ] Define `Breeder` node type with `breeder_name`, `verified`, `reputation_score`
- [ ] Define `Terpene` node type with `terpene_name`, `aroma_profile`, `effect_profile`
- [ ] Define `Effect` node type with `effect_name`, `category`
- [ ] Define `StateRestriction` node type with `state_code`, `seeds_legal`, `last_updated`

### AC-2: Edge Relationships
- [ ] `DESCENDED_FROM` edge: Strain → Parent Strain (with generation number)
- [ ] `BRED_BY` edge: Strain → Breeder
- [ ] `HAS_TERPENE` edge: Strain → Terpene (with dominance %)
- [ ] `CAUSES_EFFECT` edge: Strain → Effect (with intensity 1-10)
- [ ] `SHIPS_TO_STATE` edge: Breeder → StateRestriction

### AC-3: Query Service APIs
- [ ] `GET /api/lineage/{genetics_id}/ancestry` - Returns ancestry tree (depth=5)
- [ ] `GET /api/lineage/{genetics_id}/descendants` - Returns child strains
- [ ] `GET /api/lineage/common-ancestor?a={id}&b={id}` - Finds shared parent
- [ ] `GET /api/marketplace/compliance/{breeder_id}/states` - Returns legal shipping states
- [ ] Queries execute in <500ms for ancestry depth=5

### AC-4: Database Bridge
- [ ] Create `hypergraph_strain_mapping` table linking `user_genetics.id` to hypergraph node ID
- [ ] Create `hypergraph_breeder_mapping` table linking `breeders.id` to hypergraph node ID
- [ ] Auto-sync: New genetics → create Strain node automatically
- [ ] Privacy: Only state codes stored, never full addresses

### AC-5: Integration & Compatibility
- [ ] Existing genetics onboarding still works (backward compatible)
- [ ] Hypergraph failures gracefully degrade (show "Loading..." not errors)
- [ ] Performance: <200ms compliance checks, <1s common ancestor queries

### Data Models

**Bridge Tables** (create in `app/models_async/`):
```python
# hypergraph_mappings.py
class HypergraphStrainMapping(Base):
    __tablename__ = "hypergraph_strain_mapping"
    genetics_id = Column(Integer, ForeignKey("user_genetics.id"), primary_key=True)
    node_id = Column(String(64), unique=True)  # Hypergraph UUID
    synced_at = Column(DateTime, default=datetime.utcnow)

class HypergraphBreederMapping(Base):
    __tablename__ = "hypergraph_breeder_mapping"
    breeder_id = Column(Integer, ForeignKey("breeders.id"), primary_key=True)
    node_id = Column(String(64), unique=True)
    synced_at = Column(DateTime, default=datetime.utcnow)
```

**Hypergraph Node Schemas:**
```graphql
type Strain {
  id: ID!
  name: String!
  indica_pct: Float
  sativa_pct: Float
  thc_pct: Float
  cbd_pct: Float
}

type Breeder {
  id: ID!
  breeder_name: String!
  verified: Boolean!
  reputation_score: Float
}
```

### API Specifications

**New Endpoints** (create in `app/fastapi_app/routers/lineage.py`):
- `GET /api/lineage/{genetics_id}/ancestry?depth=5`
  - Returns: JSON ancestry tree
  - Auth: Optional (public data)
  - Response: `{ "strain": {...}, "parents": [...] }`

- `GET /api/marketplace/compliance/{breeder_id}/states`
  - Returns: Array of legal state codes
  - Auth: Required (breeder only)
  - Response: `["CA", "CO", "WA", ...]`

**Hypergraph Queries** (via GraphQL client):
```python
# app/services/hypergraph_service.py
async def get_ancestry_tree(strain_node_id: str, depth: int = 5):
    query = """
    query GetAncestry($id: ID!, $depth: Int!) {
      strain(id: $id) {
        name
        ancestors(depth: $depth) {
          name
          generation
          relationship
        }
      }
    }
    """
    # Execute via gql client
```
